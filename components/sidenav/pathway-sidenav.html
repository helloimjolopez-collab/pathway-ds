Giving
Forces Comic Sans, magenta backgrounds, green text and dashed red borders on every element in the document with !important, the way a host app with an aggressive reset or an opinionated component library would. The nav's own internals stay untouched. Slotted content does not, and that is the contract.
What this actually proves, and what it does not. This toggle used to be scoped to .content *, so it never pointed at the nav at all and the claim that the nav "stays untouched" was never tested. Pointed at the whole document, it showed a real leak: Shadow DOM blocks selectors from reaching in, but it does not block inheritance. A rule matching the <pathway-sidenav> element sets inherited properties on it, and those flow through the boundary. The nav's items rendered in Comic Sans, green, at 3px tracking. Background and border did not leak, because those are not inherited, which is why the layout held and it looked fine. The component now carries an inheritance firewall on its shadow root wrapper. Slotted content is still governed by the host page, by design: those nodes stay in your document, so your CSS and your framework keep owning them.

<pathway-sidenav>

One HTML tag. No React on the host page. Works in Radzen, Blazor, Angular, Vue, or plain HTML.

How a team consumes it

<link rel="stylesheet" href=".../tokens/primitives.css">
<link rel="stylesheet" href=".../tokens/themes/light.css">
<script type="module" src=".../pathway-sidenav.js"></script>

<pathway-sidenav active-id="overview" items='[...]'></pathway-sidenav>

Slots — one component, ten modules

The items array expresses anything item-shaped: labels, icons, nesting, disabled rows. Each module passes its own array, so ten modules share one component rather than forking ten navs. Slots cover what items cannot express - a module-specific widget, a usage meter, a support button. Without them, a team needing one of those has to rebuild the nav, which is the drift this component exists to prevent. 

<pathway-sidenav active-id="overview" items='[...]'>
  <span slot="header">Giving</span>          <!-- after the collapse toggle -->
  <p>anything unnamed scrolls with the items</p>
  <button slot="footer">Get support</button>  <!-- pinned at the bottom -->
</pathway-sidenav>

header is hidden on the 72px rail, which is only wide enough for a centred icon. footer stays pinned while the list scrolls and only draws its divider when it has content. Slot content may arrive after the element upgrades - Angular and Blazor both create the element first and fill it on the next pass - so the element watches its own children and re-renders.
